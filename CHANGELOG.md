## [0.1.0] - 2026-11-24

Initial development release (pre-release, unverified on macOS).

### Added

- Welcome screen with a bundled sample project (Pedestrian Truss Bridge), new project, open project
  and a recent-projects list that shows whether each project is still available.
- Two-step onboarding: choose one of five engineering disciplines, then one of 21
  discipline-specific project archetypes.
- Workspace with a toolbar, a collapsible and resizable explorer organised into four phases (the
  Phase 3 technical assets folder mirrors the project folder on disk), breadcrumbs, a status bar,
  keyboard shortcuts (Ctrl/Cmd+N, O, S, B and F) and protection against losing unsaved changes.
- Requirements (REQ-###) with mandatory, objective or preference classification, verification
  method and status, and evidence. Verified status is never set automatically.
- Engineering arguments (ARG-###) with problem statement, objective, alternatives, and a weighted
  decision matrix (scores 1 to 5, higher is more favourable, cost included). Missing scores are
  kept as incomplete rather than treated as zero, and ties are shown explicitly.
- Mandatory constraint evaluation in decision matrices: a failed constraint makes an alternative
  ineligible, and an unverified constraint makes it provisional.
- Separate highest-score, eligible, provisional and user-selected results, plus a documentation
  status. Approved is an internal documentation status only, and a material change returns the
  argument to Under Review.
- Temporary sensitivity analysis, assumptions, justification, references and revisions
  (REV-A to REV-Z, then AA onwards).
- Calculations (CALC-###) with KaTeX equations (trust disabled), named variables and a restricted
  arithmetic parser. The parser does not use `eval` and does not convert units.
- Traceability as a single undirected link list, with a traceability matrix, coverage figures that
  state their denominator, and gap detection.
- Risk register using likelihood by impact scoring, with inherent and residual ratings.
- Design review checklist with automatic documentation completeness checks.
- Technical assets: import with collision handling (existing files are never overwritten
  silently), a file watcher with manual refresh, relinking of missing files, and opening assets in
  their native application. Viewers for images, SVG, PDF (PDF.js) and STL models (React Three
  Fiber).
- Reports as print-friendly HTML and as PDF (generated by Electron), covering all project sections,
  the disclaimer and outstanding items. CSV exports protect against spreadsheet formula injection.
- Persistence with debounced autosave, serialised saves, atomic writes with bounded backups,
  handling of external changes, a project lock, recovery from a corrupted manifest, and rejection
  of projects written by a newer schema version.
- Project manifest `framelytix-project.json`: versioned, validated with Zod, with relative paths and
  deterministic JSON output.
- Security hardening for the Electron application: context isolation, sandboxing, no Node.js
  integration in the renderer, a Content Security Policy, a narrow typed preload API that validates
  every IPC request, path containment within the project folder, blocked executable file types on
  import and open, and network requests blocked in production builds.
- Windows NSIS installer build (unsigned). A macOS DMG build is configured but unverified.
- Packaged-app hardening with Electron fuses: no `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS` or
  `--inspect`, app code loaded only from an integrity-checked `app.asar`, and no extra `file://`
  privileges.
- A longer list of file types that FrameLytix never imports or opens, including shortcuts, help
  files, app packages and disk images. Script files such as `.py` can be imported but are never
  opened with their associated application.
- Privacy notice (`PRIVACY.md`) describing what the app stores locally. It collects nothing.

### Changed

- The installer no longer ships an unused `node_modules` folder, which removes about 130 MB of
  unused code and native binaries.
- GitHub Actions are pinned to exact commit SHAs, checkouts do not keep credentials, and Dependabot
  proposes monthly updates.
- The disclaimer now states that FrameLytix does not replace the review or seal of a licensed
  professional engineer.
